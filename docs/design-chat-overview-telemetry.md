# 聊天概览面板设计说明（遥测舱风格）

> **本文档记录设计决策与口径，不是逐行复制代码的实现清单。**
> **唯一事实来源是 `frontend/src/components/panels/ChatOverviewPanel.vue`。**
> 早期版本曾在本文档里整块复制 `<style>`/`<script>`，结果每迭代一次就要同步一次、很快失真；
> 已改为"只记决策 + 口径 + 陷阱"，代码一律看组件文件。
>
> 改动范围：**只动 `ChatOverviewPanel.vue` 一个文件**。

## 1. 目标与原则

- **中性底上做层次**：卡面/边框/文字全走 `--el-*`，深浅主题自动适配。
- **数据可视化做装饰**：Hero 的"7 个总量 + 一张 7 线叠加走势图" + 轮次卡的 token 构成条，让"酷"来自数据本身。
- **动效只做反馈**：无常驻循环动画，只留 hover 与数据过渡。
- **可折叠**：整个 Hero（7 个数字 + 走势图 + 深链行）可收起，折叠后只留标题行。折叠控件是**和刷新按钮同款的 24px 圆形图标按钮**（带边框、箭头用 SVG，折叠后旋转 -90°）——最初做成 11px 的裸 `▸/▾` 字形，太小且看不出能点，已废弃。

## 2. 硬约束（血泪清单，别踩）

1. 不改任何其他文件（RightPanel.vue、stores、api 一律不碰）。
2. 不引入新依赖，**特别是不引入图表库**：项目里没有 echarts / chart.js，所有可视化都是手写 SVG/CSS。加图表库会破坏"零依赖可视化"的现状。
3. 不改数据获取逻辑（`fetchAllMessages` / `buildRounds` / `loadOverview`）。
4. 不删模板已有信息（深链复制、轮次/工具/耗时、各指标）。
5. 保持 `prefers-reduced-motion` 支持。
6. **深色主题分支直接写 `html.dark .some-class`，禁止写 `:global(html.dark) .some-class`。**
   本仓库构建链会把它压成 `html.dark{...}`，选择器被丢弃：变量声明侥幸能靠继承生效，**属性声明会静默失效**（落到根元素上）。已核实 `AppHeader.vue` / `LeftSidebar.vue` / `AgentManagerDialog.vue` 都存在此隐患（它们的深色样式其实没生效，只是症状不可见）。
7. **缺失值 ≠ 0**：无 usage 的轮次要让折线**断开**并排除出极值计算；计数/耗时类的 `0` 是真实值，照画在底部。两者混同会把曲线砸出假坑。
8. **7 个量量纲差 6 个数量级**（总输入 10⁶ ↔ 工具次数 10⁰），叠加图里每条线必须**各自归一化**：纵轴只表"形状"，不表绝对大小。

## 3. 口径（最容易搞错的部分）

| 指标 | 数据来源（每轮 = 一条 user 消息到下一个 user 消息之间） | 口径提醒 |
|---|---|---|
| 当前窗口 | `round.windowInput` = 该轮**最后一次**模型调用的输入 | 是"最后一帧"快照，不是该轮输入之和 |
| 总输入 | `Σ usage.rounds[].inputTokens` | **已包含**缓存命中部分 |
| 总输出 | `Σ usage.rounds[].outputTokens` | |
| 总缓存 | `Σ usage.rounds[].cacheReadTokens` | **⊂ 总输入**（子集，不是并列项） |
| 总模型调用 | `Σ usage.rounds.length` | 一次提问里工具循环会反复调模型 |
| 总工具次数 | `Σ usage.toolCallCount` | 有 `toolCalls.length` 兜底 |
| 总耗时 | `Σ usage.totalDuration`（该轮） | 会话级 = `Σ` 各轮 |

另外三条必须记住的：

1. **"轮"有两个意思**：标题栏的「N 轮」= 用户提问数（`rounds.length`）；走势图里的「模型调用」= 模型调用次数。两者不是一回事。
2. **摘要（压缩）调用不进 `usage.rounds`**：`stream_utils.split_chat_usage_rounds()` 会过滤 `source == "summarize"` 的行，但 `http_traces` 记录**全部** LLM 请求。所以"模型调用次数"和"HTTP 次数"不严格相等（压缩过的长会话 HTTP 更多）。这也是**没有把 HTTP 次数当指标**的原因——它和"模型调用"重复。
3. **两条落库路径口径不一致（既有问题）**：`sse.py` 存过滤后的 `chat_usage`，`agent_runner.py` 存未过滤的 `usage_rounds`。

**已知会产生"断口"的真实数据情况**（实测归类：拿 `ff3c876d` 会话的库 + 后端日志 + `llm_usage` 三方对账得来）：

| 成因 | 现象 | 实测例子 |
|---|---|---|
| **运行被取消** | 取消得太早、什么都还没产出 → 后端一条 assistant 消息都不存；该轮在本会话 `llm_usage` 里**零记录**（usage 是整个 run 结束时批量落库的） | `#24`/`#25`：日志里 `POST /runs/cancel` 之后紧跟一个新的 `runs/stream` |
| **模型调用报错** | run 直接死掉，同样一条都不落库 | `#7`：`openai.BadRequestError 400 — Model only support text input`（当时模型组只收文本，而历史里有图片），err 日志有完整 traceback |

**关键：取消 ≠ 必然断口。** 若取消前该轮已经产出了内容或工具调用，后端照常落库——实测 `#21` 被 `runs/cancel` 打断，但仍留下 1 条带 usage 的 assistant 消息，**没有断口**。

这类轮 7 个指标全为 `null`，折线在对应 x 位置断开；相邻多轮缺失时看起来会像"两张图拼在一起"（**这是如实呈现，不是渲染 bug**）。

## 4. 视觉规格

### 4.1 Hero 结构

```
标题行：[折叠按钮] 聊天概览            [N 轮] [刷新]
Hero（可折叠）：
  第 1 行 4 格：当前窗口 / 总输入 / 总输出 / 总缓存
  第 2 行 3 格：总模型调用 / 总工具次数 / 总耗时
  一张 7 线叠加走势图（viewBox 0 0 100 56）
  会话深链行（跟随 Hero 一起折叠）
```

- 每个格子 = **会话级总量**；走势统一放在下面那张叠加图里。
- 格子标签前有一个 **6px 色点**，颜色与该指标在走势图里的那条线一致——这是唯一的"图例"，不额外画图例行。
- **每个格子同时是走势图的开关**（语义见 §4.5），所以它是 `<button>` 而不是 `<div>`。
- 第 2 行只有 3 格，列数要跟着改成 3 列（`repeat(3, 1fr)`），否则右侧会留一个空列。

### 4.2 走势图（7 条线叠加）

| 属性 | 值 |
|---|---|
| 尺寸 | `viewBox="0 0 100 56"`，CSS `width:100%; height:56px`，`preserveAspectRatio="none"` |
| 内边距 | x: 2，y: 3（viewBox 单位） |
| 线 | `stroke-width: 1.25`，`stroke-opacity: 0.85`，圆角连接，`vector-effect="non-scaling-stroke"` |
| 归一化 | token 四项 `min-max`；总模型调用/总工具次数/总耗时 `0→max` |
| x 轴 | 按**有效轮的下标**铺满（7 条线共享同一布局） |
| 整轮缺失 | **不占位**——这些轮从 x 布局里整个剔除（理由见下） |
| 单条线内部缺失 | 该点跳过 → 折线断开（这是真的稀疏，断开才对） |
| 单点段 | 补一个 `+0.8` 单位的微小横段，保证"只有一轮"时可见 |
| 全 0 序列（`zero` 模式） | 贴底（不是浮在中线） |

**整轮缺失为什么"不占位"（踩过坑后的定案）**

一个轮次要么 7 个指标全有，要么全没有（run 被取消 / 模型报错 → 一条都没落库）。它是**"缺失的时间桶"，不是"序列内部稀疏"**——这个区分决定了做法：

- 早期做法是让缺失轮照样占 x 位置、7 条线一起断开。实测一个 32 轮的会话里，**每条线被切成 4 段**，读起来像"几张图拼在一起"，被误判成渲染 bug。
- 改成不占位后，同一份数据每条线都是**连续的 1 段**（28 个点铺满），且**不伪造任何数据**——只是不给空桶留位置，属稀疏序列的标准处理。
- 代价是横轴间距失真，但这张图**没有 x 轴刻度、没有日期标签**，读者无从察觉，所以代价 ≈ 0。
- **信息不能因为形体而丢**：图左上角显式写「N 轮无数据」，`title` 里说明原因（运行被取消或模型报错）。
- ⚠️ 如果以后给这张图加上 x 轴刻度或日期，"不占位"就开始骗人（间距会被误读成时间）。那时必须改回**"保留位置 + 缺失区间铺 4~6% 透明度的中性竖带"**（Grafana 那套）。**且不要叠加虚线桥接**：56px 高、7 条线，两种修饰就是噪声。
- ❌ 永远不要置 0 或前值填充：会出现"7 条线同时砸到底再弹回来"的假坑，比断口难解释十倍。

### 4.3 7 条线的颜色（功能性用色）

叠加之后"位置"不再是区分手段，只能靠色相，所以每条线必须一个颜色——这等同于图表图例，不是装饰性彩虹：

| 指标 | `--series` |
|---|---|
| 当前窗口 | `#4a9eff` |
| 总输入 | `#f0a94a` |
| 总输出 | `#67c23a` |
| 总缓存 | `#b06ae0` |
| 总模型调用 | `#e36d8a` |
| 总工具次数 | `#2fb8ad` |
| 总耗时 | `#8d97a5` |

实现方式：`--series` 定义在 `.series-<key>` 上，色点（`background`）与折线（`stroke`）共用同一个类。

### 4.4 轮次卡的 token 构成条

| 段 | 画法 |
|---|---|
| 缓存命中 | 淡暖底 `var(--comp-warm-soft)` + 45° 斜纹（`color-mix(warm 70%) 0 1px, transparent 1px 6px`） |
| 未命中输入 | 实心 `var(--comp-warm)` |
| 输出 | `var(--el-color-success)` |
| 条高 | **5px**（3px 装不下斜纹，会糊成一块） |

暖色两套主题值：浅色 `#c97a12` / `rgb(201 122 18 / 30%)`，深色 `#f0a94a` / `rgb(240 169 74 / 20%)`。
构成条只用**纹理**区分缓存与新增，不引入第三个色相。

### 4.5 交互：点指标格 = 只看这条曲线

格子本身就是图例，所以直接让格子当开关（默认 7 条全画）：

| 操作 | 结果 |
|---|---|
| 全画时点某格 | **只看这一条**（一次点击到位，不用先关掉别的 6 条） |
| 只看这一条时，再点同一格 | 恢复全画 |
| 只看某几条时，点其它格 | **追加**进去（可任意组合） |
| 组合里点掉某格 | 取消该条；**点掉最后一条 → 回到全画**（不是回到空） |
| 依次点满 7 格 | 归一到"全画"（避免出现"只看 7 项"这种废话状态） |
| 点图旁「显示全部」按钮 | 7 条全画 |
| 点图旁「隐藏全部」按钮 | 一条都不画（空图 + 居中提示文案） |

状态用一个 `soloKeys: ref<SeriesKey[] | null>` 表达三态：`null` = 全部显示、`[]` = 全部隐藏、非空数组 = 只看这几条。
两个按钮按当前状态置灰（已全画 → "显示全部"禁用；已全隐藏 → "隐藏全部"禁用），非全画时左侧显示「已显示 N / 7」。

**"空图"的唯一入口是「隐藏全部」按钮**——格子点击路径永远不会走到空（点掉最后一条即回到全画）。空图时必须叠一句居中提示文案，不要留白得莫名其妙。
未选中的格子整格变淡（`--el-text-color-placeholder`）、色点变灰——**格子状态必须与图上实际画出的线一致**。

## 5. 其它约定

- 数字：`'JetBrains Mono', 'Fira Code', monospace` + `font-variant-numeric: tabular-nums`。
- 次数类不做 k 缩写（`formatCount`；"90 次"不能显示成"0.1k"）。
- 轮次卡：中性底 + 左轨色条，**只有最新一轮**点亮强调色。
- 交互：点轮次卡跳转消息；刷新按钮带 `is-loading` 转圈；`uiStore.activeTab === 'overview'` 时才自动刷新。

## 8. 验收清单

1. `cd frontend && npm run build` 通过，无 TS/CSS 报错、无 Vue 编译告警。
2. 源码搜索确认旧值已清空：`accent-`、`heroAurora`、`heroSheen`、`cardSheen`、`sparkPoints`、`cell-spark`、`hero-foot`、`hero-cell-window`、`avgMs`、`is-warm/is-success/is-neutral`（本组件内）。
3. 深浅主题各看一遍：Hero 中性底 + 点阵纹理；7 个色点与 7 条线颜色一一对应；换主题后暖色切档、斜纹仍可辨；无写死深色残留。
4. 折叠：点标题行右侧的圆形折叠按钮能收起/展开整个 Hero（含深链行）；折叠后只剩标题行，刷新与轮数仍在，且按钮里的箭头转向朝右。
5. 数据边界：
   - 只有 1 轮：7 条线各显示一个微小横段，不空白不报错；
   - 某轮**整轮无数据**：该轮不占位，线保持连续；图左上角出现「N 轮无数据」，悬停能看到原因；
   - **单条线内部**某轮缺值（如只有 token 没有耗时）：该点跳过、折线断开，且不参与归一化（不出现砸到底的假坑）；
   - 整个会话一条有效数据都没有：图中央提示「还没有可用的用量数据」，不报错；
   - 全场工具调用为 0：总工具次数那条线**贴底**；
   - 缓存 > 输入的脏数据：构成条不溢出、不出现负宽度或 NaN。
6. 开启系统「减少动态效果」：刷新按钮不转圈、卡片无过渡动画。
7. 功能回归：点轮次卡跳转消息；复制深链正常；自动刷新正常。
8. 布局回归：下排只有 3 格时**等宽铺满、右侧不留空列**。
9. 交互（§4.5）：点任一指标格 → 只剩那条线；再点它 → 7 条全回来；点第二格 → 两条同时画；把选中的点光 → 自动回到全画。
10. 两个按钮：「显示全部」→ 7 条全画（点完该按钮置灰）；「隐藏全部」→ 空图 + 居中提示文案（点完该按钮置灰）；两者可直接往返。
11. 图左上角那行小字：只在有额外信息时出现，内容是「已显示 N / 7」与「M 轮无数据」用 ` · ` 拼起来；全画且无跳轮时**什么都不显示**。
11. 开关一致性：未选中的格子变淡、色点变灰，且**格子状态与图上画出的线完全一致**（不会出现"格子亮着但线没画"或反之）。

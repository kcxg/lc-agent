# 工具调用参数预览设计

**日期**: 2026-07-20
**状态**: 已确认，待实现规划

## 背景与目标

工具调用卡片当前对所有数组参数统一添加 `A.`、`B.`、`C.` 前缀。该规则原为 `ask_user` 的候选选项设计，却错误应用于所有工具参数。数组元素为对象时，模板字符串会隐式调用对象的默认字符串转换，页面显示为 `[object Object]`，丢失实际参数内容。

目标：

1. 仅在 `ask_user` 的选项参数中保留字母编号预览。
2. 其他数组和对象以紧凑单行 JSON 展示，能看见完整结构而不显著增加卡片高度。
3. 保持标量参数和 200 字符截断的现有行为。
4. 不修改 `ask_user` 的中断、恢复及自然语言回答链路。

## 设计方案

在 `ToolCallCard.vue` 的参数格式化函数中，根据工具名后缀与参数名区分 `ask_user.options` 和普通复合值。框架会保留用户指定的工具名或生成 `{group}__{function}` 名称，因此用 `endsWith('ask_user')` 同时覆盖 `ask_user` 和带组名前缀的工具名。

### 参数展示规则

| 参数类型 | 展示规则 |
| --- | --- |
| `ask_user` 的 `options` 数组 | 每项显示稳定的 `A.`、`B.`、`C.` 编号及选项内容 |
| 其他数组 | `JSON.stringify(value)` 的紧凑单行 JSON |
| 普通对象 | `JSON.stringify(value)` 的紧凑单行 JSON |
| 字符串 | 原始文本 |
| 数字、布尔值、`null` | 当前 JSON 文本表示 |

示例：

```text
queries: [{"query":"LangChain 最新文档","limit":10,"searchMode":"auto","engines":["bing"]}]
```

### ask_user 交互边界

`ask_user.options` 的 A/B/C 编号是交互提示的一部分，但工具调用卡片只负责展示：

- 用户点击选项时，现有前端继续将选项文本作为恢复值提交。
- 用户在自由输入框填写 `A`、`B` 或自然语言时，现有链路继续原样传递用户输入，并由工具结果提供完整选项对照给模型理解。
- 不在前端或后端新增正则解析、字母到选项的强制映射，避免把自然语言理解硬编码进协议。

### 截断与异常值

- 保持格式化结果超过 200 字符后追加 `...` 的规则，限制工具卡片高度。
- 对无法 JSON 序列化的异常值采用安全的字符串回退，确保单个异常参数不影响整张工具调用卡片渲染。

## 改动范围

- 修改 `frontend/src/components/chat/ToolCallCard.vue` 的参数格式化逻辑。
- 不修改 SSE 协议、`ask_user` 工具定义、中断恢复逻辑、数据库或 Agent 行为。

## 验收场景

1. 普通工具的对象数组参数显示为单行 JSON，且不含 `[object Object]`。
2. 普通字符串数组显示为单行 JSON，不带 A/B/C 前缀。
3. `ask_user.options` 仍显示 A/B/C 前缀和选项文本。
4. `ask_user` 用户点击选项和自由文本回答均保持当前的模型可见信息与恢复行为。
5. 超长参数仍在 200 字符后截断。

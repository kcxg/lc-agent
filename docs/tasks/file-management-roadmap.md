# 文件管理增强路线图

背景：文件区现状为只读文件树 + 只读内容预览 + 文件名搜索，无右键菜单；图片等二进制一律拦截提示。本计划按价值排序先做 5 项。

执行顺序：f1 → f2 → f3 → f4 → f5（先补“动手能力”和预览短板，再做搜索和导航）；e1~e6 文件可编辑保存已于 2026-09-15 完成。

已完成（2026-09-15）：e1~e6 可编辑保存
- e1 后端 read：行数上限提至 200_000，返回 mtime/总行数/截断/换行符/BOM/是否 UTF-8 可编辑标记。
- e2 后端 save：`POST /tools/project/file/save`，mtime 乐观锁、保留换行符与 BOM、复用 validate_write_path 越权校验。
- e3 store：dirty/saving 状态、savedCode 基线、save() 动作、editable/readonlyReason 透传。
- e4 编辑器：新增 `CodeEditor.vue`（CodeMirror 6，虚拟滚动 + 语法高亮 + oneDark 主题），FileEditorPane 双模式——可编辑文件走 CodeMirror，只读文件保留 hljs 静态渲染；跳行/搜索均按模式分流；Ctrl+S 保存；关闭脏文件弹确认；标签页显示未保存圆点。
- e5 降级：内容 >500KB 关闭语法高亮（heavy 模式）；Markdown 维持预览态不提供编辑。
- e6 验证：vue-tsc 通过、vite build 通过、restart-bfzs 完整重启、save 路由已注册（未认证返回 401）。

通用约束：
- 后端路径操作必须复用 `lc_agent/tools/system_tools/_config.py` 的 `validate_read_path` 及 `tools.py` 的项目根解析逻辑，不得绕过越权校验。
- 不写历史数据兼容迁移；localStorage key 新增必须加前缀 `lc-agent:` 避免冲突。
- 每个任务完成标准：`npx vue-tsc --noEmit` 通过、`npm run build` 通过、相关契约测试通过；改了 `.py` 则走 restart-bfzs 完整重启验证。

## f1 文件增删改（最高优）

目标：文件树从“只能看”变成“能动手”。

范围：
- 后端新增接口：新建文件/文件夹、重命名、删除（建议放在 `lc_agent/server/routes/tools.py`，与 `/tools/file/read` 同路由组，统一走项目根解析 + 路径校验；删除仅允许项目目录内，禁止删除项目根）。
- 前端文件树右键菜单：新建文件、新建文件夹、重命名、删除、复制路径、复制相对路径。
- 删除需二次确认弹层；操作后局部刷新树节点 + 若影响已打开标签（重命名/删除）则同步更新 opened-files store。

验收：
- 新建/重命名/删除后树实时更新，不整树闪烁。
- 删除已打开文件时对应标签自动关闭；重命名时标签路径同步更新。
- 越权路径（如 `..`、绝对路径逃逸）后端拒绝。

风险：误删。缓解：删除二次确认 + 后端禁止删项目根。

## f2 图片预览

目标：png/jpg/svg/gif/webp 在文件区直接渲染，docs_pic 类目录可看。

范围：
- 后端 `/tools/file/read` 对图片后缀返回可展示方式（二进制嗅探保持，但图片走单独分支；建议返回 base64 或提供文件流 URL，优先复用现有鉴权）。
- 前端 opened-files store 增加 `asImage` 判定；FileEditorPane 增加 `<img>` 预览分支（含自适应缩放、深色背景棋盘格可选）。
- svg 按图片渲染（注意 XSS：用 `<img>` 标签而非内联 HTML）。

验收：点击图片文件显示图片而非“二进制无法预览”；超大图不卡死（限制渲染尺寸或懒加载）。

风险：svg 内联脚本 XSS。缓解：只用 `<img src>` 方式。

## f3 标签页管理增强

目标：对标 VS Code 基础标签操作。

范围（均在 opened-files store + FileEditorPane）：
- 标签右键菜单：关闭、关闭其他、关闭右侧、关闭全部。
- 固定标签（pinned，关闭全部时保留，顺序置前）。
- 恢复已关闭标签（Ctrl+Shift+T 或菜单项，维护关闭栈）。
- 标签过多溢出处理：横向滚动 + 激活标签自动滚入可见区。

验收：上述操作均生效且持久化（固定状态、标签顺序随 localStorage 恢复）。

风险：持久化结构变更。缓解：读取旧存档时做字段缺失容错。

## f4 全文内容搜索

目标：在项目内按文件内容 grep 搜索并跳转。

范围：
- 后端新增内容搜索接口（建议复用 project search 路由组；必须做二进制文件排除、单文件大小上限、结果数量截断、超时保护）。
- 前端文件区新增“文件名 / 内容”搜索模式切换；内容搜索结果按文件分组显示匹配行片段；点击跳转打开文件并定位到对应行（FileEditorPane 需支持跳行 + 高亮）。

验收：输入关键字返回 `文件:行号:片段` 列表；点击打开对应文件并滚动到该行；大仓库搜索不超时卡死。

风险：大项目全量扫描慢。缓解：结果截断 + 忽略目录（node_modules、.git、__pycache__ 等）。

## f5 面包屑 + 文件定位

目标：解决“看了文件不知道在哪、树里找不到文件”问题。

范围：
- FileEditorPane 顶部增加路径面包屑（`项目名 / src / … / Foo.vue`），点击任意层级在文件树中展开定位。
- 文件树自动定位：切换激活标签时，树自动展开并滚动到对应节点、高亮。
- “在树中显示”按钮（点击手动定位一次，应对自动定位被用户手动滚动打断的场景）。

验收：切换标签树跟随定位；面包屑每级可点且定位正确；长路径省略号显示但 title 完整。

风险：自动滚动与用户手动浏览冲突。缓解：仅在标签切换时自动定位，树内滚动不反向干扰编辑器。
